## 🔴 P0 — 真实可见的 bug,建议优先修

### P0-1. 历史记录 tab 打开就是空表("共 0 条"),但 `app/data/runs/` 实际有 10+ 条 manifest

**实测**:点开「历史记录」tab,Dataframe `tbody tr` 数量 = 0,计数显示"共 0 条"。
但磁盘上 `app/data/runs/*.json` 有十几份。

**根因** (`app/scail2_app.py:1140` `_build_history_tab()`):

- Dataframe 初始 `value` 没设;
- 只有 `refresh_btn.click` / `preset_filter.change` / `status_filter.change`
  三个事件会触发 `_refresh_history_filtered`;
- **没有任何 `demo.load(...)` 或 tab 可见性钩子在首次打开 tab 时拉一次数据**。

**用户影响**:首次进历史 tab 会以为"我跑过的都没记录下来",这是一个会让人
怀疑数据丢失的体验。

**修法**:加一个
`demo.load(fn=_refresh_history_filtered, inputs=event_inputs, outputs=event_outputs)`,
或在 main tabs 上加 `change` 钩子。补测试 `test_history_loads_on_startup`
锁回归。

### P0-2. 左侧导航 Radio label 末尾泄漏内部 `category` 英文标识

**实测 DOM**:

```html
<span>🖼️ 文生图 (Z-Image-Turbo) · image</span>
```

每项都以 `· image` / `· video` / `· audio` 结尾。

**根因** (`app/scail2_app.py:2450`):

```python
def _wf_label(w):
    cat = w.get("category", "other")
    icon = _category_icon(cat)
    suffix = f" · {cat}" if cat != "other" else ""   # ← 这行
    return f"{icon} {w['display_name']}{suffix}"
```

**问题**:

- emoji 前缀已经表达了类别 (🖼️ / 🎬 / 🔊),`· image` 是冗余信息 → 视觉噪声;
- 这是一个**纯中文 UI**,突然冒出英文 `image / video / audio` 很突兀,
  破坏语言一致性;
- `· ` 间隔号 + 英文小写词的组合读起来像"调试残留",普通用户看不懂这是干嘛的;
- 后缀把 Radio 选项顶满 200px (`min_width=200`),文字换行成两行
  (实测每项 `h=60px`,中文部分单行 `~40px` 就够)。

**建议**:直接删掉 `suffix` 那行。emoji 已表达类别,无需文本后缀。
顺带把 padding 从 `var(--space-3) var(--space-4)` 降到
`var(--space-2) var(--space-3)`,9 项能从 ~540px 压到 ~380px。

> 这条改动跟下方 P2-5 的"导航项偏高"是同一个根,一起改最划算。

## 🟠 P1 — 对比度 / 可读性硬伤 (有 WCAG 数据支撑)

### P1-3. `--text-faint` 对比度 2.85,低于 WCAG AA 4.5

量了 `tokens.css` 里所有 text token 在卡片底 (`--bg-card: #1a1d23`) 上的对比度:

| token | 值 | 对 card bg 对比度 | WCAG AA (4.5) |
| --- | --- | --- | --- |
| `--text-primary` | `#f3f4f6` | 15.34 | ✅ |
| `--text-secondary` | `#c2c7d2` | 9.96 | ✅ |
| `--text-muted` | `#8b909b` | 5.27 | ✅ 勉强 |
| **`--text-faint`** | **`#5f6470`** | **2.85** | **❌ 不达标** |

**受影响位置** (`tokens.css`):

| 行 | 用途 |
| --- | --- |
| `235` | `.btn-run-primary:disabled` 文字色 |
| `304` | `.btn-run-secondary:disabled` 文字色 |
| `385` | `.btn-run-primary:disabled:not(.is-running)` 文字色 |
| `1074` | **`.file-dropzone svg` — 上传区占位图标色** |

最伤的是 `:1074` —— 拖拽区的占位图标在暗底上几乎看不清。`235/304/385` 是
按钮 disabled 态文字,disabled 文字本来就浅,但 2.85 连"能瞄到"都算不上。

**建议**:把 `--text-faint` 从 `#5f6470` 提亮到 `#717785` 左右
(对比度 ~3.8,作为"非关键辅助信息"可接受);或直接和 `--text-muted` 合并,
项目里只保留一档"次要文字"。

> 注:`AGENTS.md` "Light mode removed" 段记了上次"明亮模式对比度不达标 → 直接
> 砍掉 light mode"的决策。**这里是暗模式自身**也有一档没过线,不是亮模式特有。

## 🟡 P2 — 布局 / 空间利用

### P2-4. 容器 `max-width: 1400px`,宽屏左右大量留白

`tokens.css:131`:

```css
.gradio-container {
  max-width: 1400px !important;
}
```

- 1920×1080 显示器上,两侧各留 ~260px 纯黑死区;
- 这是一个**本地工具**(不是手机端网页),目标用户基本都在桌面大屏,
  1400 上限偏保守;
- 右侧预览栏 (scale=7) 在 1400 容器里也就 ~800px,而生成出来的图很多是
  720×1280 竖图,显示得很小。

**建议**:放宽到 1600~1800px,或干脆 `max-width: none` + 两侧只留最小 padding。
这是工作台不是阅读型页面,横向空间应该吃满。

---

### P2-5. 没有 app 标题 / 品牌区,首屏直接是 Radio + 表单

**实测**:页面上**没有任何 h1 / h2**(probe 结果 `HEADERS: []`)。
唯一标题是每个 preset 表单里那个 `### {display_name}` (h3)。

**后果**:

- 浏览器 tab title 是 "ComfyUI Web Workflow",但页面本体没有大标题;
- 用户分不清这是哪个工具(尤其是 launcher 套了好几个 webui 时);
- "导航 / 系统"两个小标题用 `**导航**` 加 `.nav-group .prose` 渲染成
  uppercase 12px 灰字 —— 信息层级偏弱。

**建议**:`build_ui()` 最顶部 (Tabs 之前) 加一行
`gr.Markdown("# 🎬 ComfyUI 工作流运行器")` 或类似的小标题区,30 秒改动,
首屏立即有"这是一整个应用"的感觉。

---

### P2-6. 左导航每项 60px 高 + 200px 宽,9 项占 ~540px 垂直空间

偏大:

- 9 项 × 60px = 540px,加上"导航 / 系统"两个分组小标题、divider、搜索框,
  左栏总高接近 700px;
- 1080p 屏幕去掉浏览器 chrome 大概 ~950px 可视,左栏几乎顶天立地;
- 每项之所以 60px(两行),是因为 `· image` 后缀把文字挤换行(见 P0-2)。
  **删掉后缀后**每项能压回 ~40px 单行。

**建议**:跟 P0-2 一起改,删后缀 + padding 降一档,9 项能从 540px 压到 ~380px。

## 🟢 P3 — 打磨向 / 一致性

### P3-7. `body` 背景跟 `--bg-app` 不是同一个颜色(轻微但存在)

**实测**:
`body_bg = rgb(10, 15, 30)` (Gradio 主题自带的 `--bg-dark: #0a0f1e`),
而 `--bg-app: #0f1115`。两者都是深色但**色相不同**(body 偏蓝,app 偏灰),
在 `.gradio-container` 边缘能看出一圈淡淡的色差过渡。

虽然 `:root.dark { --body-background-fill: var(--bg-app) }` 设了,但 Gradio 6 的
inline `<style>` 在 `<head>` 里也写死了 `body { background: var(--bg-dark); }`,
优先级打架。

**建议**:`tokens.css` 顶部加一条 `body { background: var(--bg-app) !important; }`
一刀切。

---

### P3-8. `tokens.css` 有 449 个 `!important` + 41 个 `.gradio-container` 覆盖

47KB 的自定义 CSS,本质是在和 Gradio Soft 主题打架。不是 bug,但有两个隐患:

- **Gradio 6 → 7 升级时** `.svelte-xxxxx` 类名哈希会变。我在 DOM probe 里看到
  的 `.svelte-19qdtil` / `.svelte-e5lyqv` 如果被直接引用会瞬间失效 ——
  扫了下还好目前都是用语义 class (`.custom-radio` / `.section-header`),
  没硬编码 svelte hash;
- 但 449 个 `!important` 意味着用户 / 未来开发者很难再做局部覆盖。

不是现在要动的,但值得在 `docs/UI_STYLE.md` 里加一条"自定义优先,Gradio 原生能
表达就不覆盖"的原则复述(文档 §4 末尾其实写了,但执行上 449 个 !important
说明执行得不够彻底)。

## 总结 — 按改起来性价比排

| 优先级 | 项 | 改动量 | 收益 |
| --- | --- | --- | --- |
| P0 | 历史记录 tab 首次打开不自动加载数据 | 加 1 行 `demo.load(...)` | 修复"数据丢失"错觉 |
| P0 | 导航 Radio 去掉 `· image/video/audio` 后缀 | 删 1 行 `suffix = ...` | 视觉降噪 + 项回到单行 |
| P1 | `--text-faint` 提亮 (2.85 → ~3.8) | 改 1 个 hex | 拖拽区图标 / disabled 文字可见 |
| P2 | 容器 `max-width` 1400 → 1700 | 改 1 个数 | 宽屏不再有大块死区 |
| P2 | 顶部加个 app 标题 | 加 1 行 Markdown | 首屏有"应用感" |
| P3 | `body { background: var(--bg-app) !important; }` | 加 1 行 | 消除边缘色差 |
| P3 | 状态条文案加标点 | 改 1 个字符串 | 可读性 |

**前两条 P0 建议现在就改** —— 都是几行代码,但都是用户每次用都会撞到的体验问题。
