# UI 深度重构设计稿

## 背景

当前 WebUI 的主要问题不再是某几个按钮或颜色不好看，而是整体更像技术表单页，缺少创意工作台应有的主次结构。与此同时，仓库里仍残留大量与 `历史记录` 相关的文档、样式和测试叙事，造成实现与规范脱节。

用户已明确两项方向：

- 永久放弃 `历史记录`
- 运行页朝“更好看、层级更清楚”的创意工作台方向深度重构

## 目标

- 永久移除 `历史记录` 的产品叙事与实现残留
- 保留 `Gradio + schema 驱动表单` 的技术基础
- 把运行页改造成更明确的创意工作台结构
- 让结果区成为视觉主角，参数区服务于创作，而不是主次混乱

## 非目标

- 不重写为 FastAPI / HTMX / Tailwind 独立前端
- 不引入营销页式 hero、插画、大面积炫技特效
- 不改变工作流 schema、ComfyUI 调度逻辑、主题持久化能力

## 新信息架构

### 顶部头部

- 显示应用名称 `ComfyUI 工作流运行器`
- 给出一条轻量定位文案
- 放置全局状态与主题入口

### 左侧导航

- 保留搜索框
- 使用更像工具导航的 workflow 列表
- 导航底部承载系统动作：刷新状态、打开输出文件夹

### 中间参数区

按用户决策顺序组织，而非按底层组件生成顺序堆叠：

1. 输入素材
2. 创作内容
3. 输出规格
4. 运行控制
5. 高级参数

### 右侧结果区

- 默认展示 example 预览，强调作品感
- 运行中展示状态、耗时、进度
- 成功后结果替换 example
- 错误统一在结果区顶部呈现
- 日志保留在底部折叠区

## 视觉原则

- 暗色创意工作台，而不是营销页或后台管理页
- 页面只保留一个绝对主焦点：`开始运行`
- 结果区的视觉权重高于参数区
- 辅助说明统一变轻变短，减少文字墙
- 减少重复边框、重复卡片、重复状态块

## 清理范围

### 必删

- `历史记录` 相关产品说明
- 指向旧历史页的文档段落
- 针对历史页的过期 E2E 断言
- `tokens.css` 中历史页专属样式区块

### 必改

- `UI_STYLE.md`
- `ADDING_WORKFLOWS.md`
- `test_e2e_browser.py`
- 运行页布局与样式

## 实施顺序

1. 统一文档与测试叙事，清除历史页残留
2. 重做运行页骨架
3. 调整参数区结构和结果区主次
4. 收敛样式 token 与视觉层级
5. 跑测试、修回归

## 验收标准

- 首屏一眼能看出“左边选工作流，中间改参数，右边看结果”
- 页面看起来像一个本地创作工作台，而不是配置堆栈
- `历史记录` 不再出现在代码、文档、测试的主叙事中
- 切 workflow 时结构稳定，保留现有表单状态契约
