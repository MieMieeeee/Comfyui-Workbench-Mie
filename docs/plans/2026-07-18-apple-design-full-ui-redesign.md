# Apple-Design 全界面重构稿

## 背景

当前运行页已经从“普通技术表单”重构为“三栏创意工作台”，方向是对的，但整体仍停留在“多个深色卡片拼接出来的工作台”。如果按 `apple-design` 的原则看，主要问题已经从“是否好看”转向“材料是否统一、主次是否绝对、操作是否足够直接”。

这次重构稿不再只修头部，而是把整个 Gradio 界面视为一个完整器物来重审：头部、导航、输入区、结果区、状态反馈要属于同一套设计系统，而不是各自成立。

## 目标

- 把当前三栏工作台统一成一套更克制、更连贯的 `apple-design` 风格界面。
- 保持 `Gradio + schema 驱动表单 + preset 预渲染保状态` 的现有架构。
- 让用户进入页面后的第一感受从“看卡片”变成“立即开始创作”。
- 让右侧结果区成为真正的主舞台，中间参数区成为服务层，左侧导航成为结构层。
- 通过材料统一、文案收束、即时反馈和更稳的空间秩序提升高级感。

## 非目标

- 不改成独立前端框架，不脱离 Gradio。
- 不追求“苹果长相”复刻，不做拟物化仿制。
- 不引入复杂手势、拖拽物理、沉重动画系统。
- 不重写工作流 schema、运行逻辑、ComfyUI 交互链路。

## 设计原则

### 1. 目的性

- 页面上的每一层都必须回答“它为什么存在”。
- 不能再让头部、工作流标题、结果卡、说明文案同时争夺注意力。

### 2. 简洁不是极简

- 减少不是删空，而是只保留真正帮助理解和操作的结构。
- 可以保留必要说明，但不保留结构已经能表达的解释性句子。

### 3. 材料统一

- 整页只保留三层材料：页面基底、结构 chrome、内容舞台。
- 不同区域的区别应来自层级，而不是每一块都长得不一样。

### 4. 结果优先

- 结果区是用户最想看到的内容，视觉权重必须最高。
- 输入区和导航区都要让位给“看结果”和“开始运行”。

### 5. 直接反馈

- 所有点击、切换、展开都应有即时、轻量、无延迟感的反馈。
- 不追求炫技动效，只追求“没有断感”。

## 当前界面诊断

### 1. 头部仍然像 Banner

- 头部已经删掉了冗余文案，但容器仍过厚、过亮、过完整。
- 它更像一张题头海报，而不是界面最上层的轻薄 chrome。

### 2. 左侧导航仍偏后台

- 导航区是一张独立卡片，内部又拆出“导航”和“系统”两块。
- 信息是清楚的，但器物感偏重，像管理后台侧栏，不像创作工具结构层。

### 3. 中间区仍然是表单思维

- 虽然字段顺序已经按用户任务逻辑调整，但视觉呈现仍是“被 section 和卡片包装的表单”。
- 用户看到的是输入分段，而不是连续创作流程。

### 4. 右侧结果区还不够像主舞台

- 当前结果区在结构上独立了，但在材料和视觉重量上仍和中间区差距不够大。
- 它还是“一个区块”，不是“整个工作台的焦点”。

### 5. 标题系统重复

- 顶部应用标题和中间工作流标题都是大标题层级，形成双主语。
- 用户需要两个“我现在在什么地方”的答案，这是不必要的。

### 6. 文案仍偏解释型

- 导航说明、工作流说明、预览说明中仍存在较多“告诉用户这里是什么”的话。
- 这些内容会降低界面的直接性和精致感。

## 新的全界面信息架构

整页按照 `Top Chrome / Navigation Rail / Creation Surface / Result Stage` 四个角色重组。

### A. Top Chrome

页面顶部不再是大 Banner，而是一条轻薄的题签层。

- 左侧：`ComfyUI 工作流运行器`
- 右侧：`黎黎原上咩` + 诗句落款
- 不再承载产品说明、状态 pills、辅助标签
- 高度明显缩短
- 背景更薄、更轻、更像浮在页面上的磨砂结构层

### B. Navigation Rail

左侧是结构导航，不是主内容卡片。

- 顶部：搜索框
- 中部：工作流选择列表
- 底部：系统状态与次级工具按钮
- 视觉上接近 source list，而不是“系统设置卡”
- 不再用重卡片来强调自身

### C. Creation Surface

中间区是“连续创作表面”，不是一连串分离表单卡。

- 顶部是一条紧凑工作流标题行，不再是一整块大头卡
- 中部是连续的输入区分段
- 底部是运行控制与高级参数
- 用户感知应是：我在一张连续工作台面上调整参数

### D. Result Stage

右侧是主舞台，是全页最稳定、最重要、最具视觉重心的区域。

- 标题轻
- 结果面板重
- example、运行中、最终结果、失败提示都进入同一个舞台系统
- 日志不再成为同级大块，而是结果舞台下的次要折叠层

## 三层材料系统

### Layer 1: 页面基底

- 整个页面共用一张连续暗色基底
- 减少块与块之间“各有自己的大背景”
- 背景更像深色空间，不像一堆深色卡片的底座

### Layer 2: 结构 chrome

适用于头部和左侧导航。

- 半透明
- 更轻的边界
- 更克制的阴影
- 可以有轻微 blur 或高光边缘，但不应显得厚重
- 作用是建立结构，不是吸走注意力

### Layer 3: 内容舞台

适用于中间输入区和右侧结果区，但权重不同。

- 中间区：轻内容层
- 右侧结果区：重内容层
- 两者同源，但右侧更有厚度、更稳、更像最终作品承载面

## 逐区重构方案

### 1. 顶部头部

#### 目标

- 从“Banner”降级为“顶层 chrome”
- 保留身份感，去掉海报感

#### 方案

- 容器高度从当前大块卡片压缩到更薄的一条
- 去掉强阴影和明显的整块发光
- 保留非常轻的边缘光和微透明磨砂
- 左侧标题更像 app title，不像营销 hero
- 右侧署名更像落款，不像第二主标题

#### 版式

- 左右继续横向布局，但整体垂直居中
- 左侧标题占绝对主导
- 右侧名字字重下降一档，字号减小一档
- 诗句更靠近名字，整体右对齐并再向内收

#### 文案

- 左侧只保留 `ComfyUI 工作流运行器`
- 右侧只保留 `黎黎原上咩` 与诗句
- 不再出现解释性副文案

### 2. 左侧导航

#### 目标

- 从“独立卡片侧栏”变为“结构导航轨”
- 减少后台感，增强工具感

#### 方案

- 导航和系统区域共用同一连续容器
- `导航`、`系统` 变成轻量区段标题，而不是小卡片标题
- 搜索框做成磨砂/低对比输入条
- 列表项做成更像 source list 的选中态

#### 选中态规则

- 轻背景
- 清晰文字
- 极细高亮竖条
- 不使用厚重块状填充

#### 系统区

- 缩到导航底部
- 只保留最关键的状态与两个工具动作
- 不应与工作流选择竞争

### 3. 中间输入区

#### 目标

- 从“漂亮表单”转向“连续任务流”

#### 方案

- 现有 `workflow-stage-header` 改为紧凑标题行
- 只显示当前 workflow 名称和一行非常轻的描述
- `step-card` 进一步去卡片感，只保留必要的段落节奏
- 每段输入不再强调“容器边界”，而强调“阅读顺序”

#### 结构建议

- 输入参数
- 运行控制
- 高级参数

其中：

- `输入参数` 保持为主段
- `运行控制` 紧跟其后，成为用户自然的下一步
- `高级参数` 明显降级，做成 quiet disclosure

#### 文案建议

- helper text 更短
- 如果字段附近已通过位置表达关系，就不再额外解释
- 描述更偏“如何使用”，少说“这里是什么”

### 4. 右侧结果区

#### 目标

- 让结果区真正成为创作舞台

#### 方案

- `作品预览` 标题弱化，不再是一块存在感很强的小节头
- 结果面板本身变成主视觉主体
- example 预览、运行中状态、完成后结果都使用同一承载表面
- 日志折叠区和帮助文案继续下沉

#### 视觉层级

- 右侧面板比中间区更厚重一点
- 使用更稳定的表面与更克制的边缘光
- 不通过大量辅助说明强调“这是结果区”，而是让结果本身说话

### 5. 状态反馈

#### 目标

- 从提示条思维改为“工作台状态层”

#### 方案

- `run-status` 和运行控制靠得更近
- 状态文本更短，更多用颜色、icon、位置来传达
- 空闲、运行中、成功、失败四态必须一眼可分
- 失败状态的文案应更像下一步操作建议，不只是报错

#### 交互反馈

- 按钮按下立即反馈
- 切换 workflow 时标题与表单用轻量 cross-fade
- 结果更新时使用短时淡入，不硬切
- accordion 展开收起更柔和

## 文案策略

### 保留

- 能直接帮助用户判断下一步动作的文案
- preset 的核心差异说明
- 错误后的行动建议

### 删除

- 能被布局结构表达的说明句
- 纯装饰性口号
- 重复解释“这是工作台/这里是导航/这里是结果”的句子

### 语气

- 更克制
- 更具体
- 更像工具，不像介绍页

## 视觉与排版规则

### 标题系统

- 应用标题：唯一 display 级
- 当前 workflow 标题：section-title 级
- 小节标题：section-label 级
- 辅助说明：meta 级

### 字体

- 全局优先使用系统无衬线
- 标题负 tracking 仅用于真正的大标题
- 小字号文字不使用统一 letter-spacing，而按层级调整
- 诗句保留书卷气，但只作为局部例外

### 间距

- 用更明显的大层级间距区分区域
- 用更克制的小层级间距组织字段
- 不再依赖容器边框制造“层次感”

## 动效与响应建议

在不脱离 Gradio 的前提下，优先补以下轻量反馈：

- 按钮 pointer-down 即反馈
- 工作流切换时标题和内容短时 cross-fade
- 结果替换时 opacity 过渡
- accordion 箭头和内容展开更柔和

不建议在当前阶段引入复杂弹簧、拖拽、物理动效，因为 Gradio 不适合承载那类重交互。

## 可访问性与兼容

- 为 `prefers-reduced-motion` 准备淡入淡出降级方案
- 为高对比模式保留更明确的边界
- 文字和容器的对比度不能因“磨砂感”下降
- 署名诗句必须始终低于主标题权重，避免阅读路径混乱

## 分阶段执行建议

### Phase 1: 统一材料

- 头部薄化
- 左侧导航去卡片化
- 工作流头区缩成紧凑标题行
- 结果区升格为更稳定的主舞台

### Phase 2: 压缩层级

- 删除多余说明文案
- 降低小节标题存在感
- 统一边框、阴影、背景透明度

### Phase 3: 微交互

- 补即时按压反馈
- 切换与展开加入短时过渡
- 结果切换改为更柔和的替换

### Phase 4: 打磨与回归

- 浏览器逐 preset 审看
- 调整导航、输入区、结果区的比例平衡
- 修测试、补文档、锁样式契约

## 验收标准

- 首屏不再像多张深色卡片堆叠，而像一个连续工作台
- 用户一眼知道：左边选任务，中间改参数，右边看结果
- 头部不再是视觉主角，但仍保有身份感
- 右侧结果区成为自然主焦点
- 页面看起来更轻、更稳、更统一，而不是更花
- 文案整体更短，仍不损失可理解性

## 最终建议

不建议继续对单一区块做零散修补。下一轮最值得做的，是按照本稿一次性完成“材料统一 + 结构减重 + 结果升格”的整体重构。这样才能真正让当前 Gradio 项目从“暗色后台工具”进到“高级创作工作台”的层级。
